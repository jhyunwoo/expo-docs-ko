# TypeScript 함수

custom build 구성에서 EAS Build 함수를 만들고 사용하는 방법을 알아보세요.

EAS Build 함수는 custom build의 기능을 확장하는 훌륭한 방법입니다. 이를 사용해 재사용 가능한 step을 만들 수 있고, JavaScript, TypeScript, Bash로 로직을 작성할 수 있습니다(자세한 내용은 config schema의 [`command` in the config schema](/custom-builds/schema#functionsfunction_namecommand)를 참고하세요). 이 가이드는 TypeScript로 함수를 만드는 과정을 안내합니다.

## EAS Build 함수 모듈 초기화하기

EAS Build 함수를 만드는 가장 쉬운 방법은 `create-eas-build-function` CLI 도구를 사용하는 것입니다. **eas.json** 파일이 있는 디렉터리에서 다음 명령을 실행하면 새 custom TypeScript 함수를 만들 수 있습니다:

```sh
npx create-eas-build-function@latest ./.eas/build/myFunction
```

이 명령은 **.eas/build** 디렉터리에 `myFunction`이라는 새 모듈을 만듭니다. 이 모듈에는 미리 생성된 모듈 구성과, 기본 TypeScript 함수 템플릿이 들어 있는 **src/index.ts** 파일이 포함된 **src** 디렉터리가 생성됩니다.

```ts
// This file was autogenerated by `create-eas-build-function` command.
// Go to README.md to learn more about how to write your own custom build functions.

import { BuildStepContext } from '@expo/steps';

// interface FunctionInputs {
//   // specify the type of the inputs value and whether they are required here
//   // example: name: BuildStepInput<BuildStepInputValueTypeName.STRING, true>;
// }

// interface FunctionOutputs {
//   // specify the function outputs and whether they are required here
//   // example: name: BuildStepOutput<true>;
// }

async function myFunction(
  ctx: BuildStepContext
  // {
  //   inputs,
  //   outputs,
  //   env,
  // }: {
  //   inputs: FunctionInputs;
  //   outputs: FunctionOutputs;
  //   env: BuildStepEnv;
  // }
): Promise<void> {
  ctx.logger.info('Hello from my TypeScript function!');
}

export default myFunction;
```

## 함수 컴파일하기

함수는 의존성을 별도로 설치하지 않아도 실행할 수 있는 단일 JavaScript 파일로 컴파일되어야 합니다. 생성된 함수의 기본 `build` 스크립트는 [ncc](https://github.com/vercel/ncc)를 사용해 함수와 모든 의존성을 하나의 파일로 컴파일합니다. 머신에 `ncc`가 전역 설치되어 있지 않다면 `npm install -g @vercel/ncc`를 실행해 설치하세요. 그런 다음 **.eas/build/myFunction** 디렉터리에서 build 스크립트를 실행합니다:

```sh
npm run build
```

이 명령은 custom function 모듈의 **package.json** 파일에 들어 있는 `build` 스크립트를 실행합니다.

```json
{
  ...
  "scripts": {
    ...
    "build": "ncc build ./src/index.ts -o build/ --minify --no-cache --no-source-map-register"
    ...
  },
  ...
}
```

`build` 스크립트는 **build/index.js**를 생성합니다. 이 파일은 builder가 함수를 실행할 수 있도록 프로젝트 archive의 일부로 EAS Build에 업로드되어야 합니다. 이 파일이 **.gitignore** 또는 **.easignore**에 의해 제외되지 않도록 하세요.

## 함수를 custom build config에 노출하기

> **참고**: 아래 예시는 이미 custom build workflow를 설정하고 이를 **eas.json**에 구성해 두었다고 가정합니다. 아직이라면 진행하기 전에 [custom build 시작하기](/custom-builds/get-started#create-a-workflow)를 참고하세요.

**.eas/build** 디렉터리에 **config.yml** 파일이 있고, 그 내용이 다음과 같다고 가정해 보겠습니다:

```yaml
build:
  name: My example config
  steps:
    - eas/checkout
    - eas/install_node_modules
    - run:
        name: Finished
        command: echo Finished
```

함수를 config에 추가하려면 **config.yml** 파일에 다음 내용을 더해야 합니다:

```yaml
build:
  name: My example config
  steps:
    - eas/checkout
    - eas/install_node_modules
    - run:
        name: Finished
        command: echo Finished

functions:
  my_function:
    name: My function
    path: ./myFunction
```

`path` 속성은 config 파일에서 함수 디렉터리까지의 상대 경로여야 합니다. 이 경우에는 단순히 `./myFunction`입니다.

이제 **config.yml** 파일에 `my_function` 함수 호출을 추가하세요:

```yaml
build:
  name: My example config
  steps:
    - eas/checkout
    - eas/install_node_modules
    - my_function
    - run:
        name: Finished
        command: echo Finished

functions:
  my_function:
    name: My function
    path: ./myFunction
```

## 함수 작업하기

조금 더 고급 예시로, 함수가 두 숫자의 합을 계산해 콘솔에 출력하고 그 값을 함수의 출력으로 내보내게 만들고 싶다고 가정해 보겠습니다. 이를 위해 **config.yml**과 **index.ts** 파일을 수정해, 함수가 `num1`, `num2`라는 두 입력을 받고 그 합계를 `sum`이라는 출력으로 반환하게 만듭니다.

```yaml
build:
  name: My example config
  steps:
    - eas/checkout
    - eas/install_node_modules
    - my_function:
        inputs:
          num1: 1
          num2: 2
        id: sum_function
    - run:
        name: Print the sum
        inputs:
          sum: ${ steps.sum_function.sum }
        command: echo ${ inputs.sum }
    - run:
        name: Finished
        command: echo Finished

functions:
  my_function:
    name: My function
    inputs:
      - name: num1
        type: number
      - name: num2
        type: number
    outputs:
      - name: sum
    path: ./myFunction
```

```ts
// This file was autogenerated by `create-eas-build-function` command.
// Go to README.md to learn more about how to write your own custom build functions.

import {
  BuildStepContext,
  BuildStepInput,
  BuildStepInputValueTypeName,
  BuildStepOutput,
} from '@expo/steps';

interface FunctionInputs {
  // first template argument is the type of the input value, second template argument is a boolean indicating if the input is required
  num1: BuildStepInput<BuildStepInputValueTypeName.NUMBER, true>;
  num2: BuildStepInput<BuildStepInputValueTypeName.NUMBER, true>;
}

interface FunctionOutputs {
  // template argument is a boolean indicating if the output is required
  sum: BuildStepOutput<true>;
}

async function myFunction(
  ctx: BuildStepContext,
  {
    inputs,
    outputs,
  }: // env,
  {
    inputs: FunctionInputs;
    outputs: FunctionOutputs;
    // env: BuildStepEnv;
  }
): Promise<void> {
  ctx.logger.info(`num1: ${inputs.num1.value}`);
  ctx.logger.info(`num2: ${inputs.num2.value}`);

  const sum = inputs.num1.value + inputs.num2.value;

  ctx.logger.info(`sum: ${sum}`);

  outputs.sum.set(sum.toString()); // Currently, outputs must be strings. This will improve in the future.
}

export default myFunction;
```

> 함수를 변경할 때마다 반드시 다시 컴파일하세요: `npm run build`.

## 요약

-   함수 작성은 custom build 기능을 여러분만의 로직으로 확장하는 훌륭한 방법입니다.
-   EAS Build 함수는 재사용 가능하므로, 여러 custom build 구성에서 사용할 수 있습니다.
-   EAS Build 함수는 shell script만으로 처리하기 어려운 더 고급 사용 사례에서 매우 좋은 선택지입니다.
-   대부분의 [내장 함수](/custom-builds/schema#built-in-eas-functions)는 오픈 소스이며, 포크하거나 직접 함수를 작성할 때 참고용으로 사용할 수 있습니다.

더 자세한 예시는 **example repository**를 확인하세요:

[Custom build example repository](https://github.com/expo/eas-custom-builds-example/tree/main) — 함수 설정, 환경 변수 사용, artifact 업로드 등 custom build 예시를 포함한 custom EAS Build 예제입니다.
