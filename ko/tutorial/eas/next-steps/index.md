# 다음 단계

EAS 여정에서 다음 단계로 무엇을 하면 좋을지 알아봅니다.

축하합니다! EAS 튜토리얼을 완료했고 주요 기능도 익혔습니다. 이제 여러분은 동작하는 [EAS project](https://expo.dev/eas)를 갖게 되었습니다.

## EAS

하지만 이것은 시작에 불과합니다. EAS 여정을 계속하기 위한 다음 단계는 다음과 같습니다:

[EAS Workflows](/eas/workflows/introduction) — 개발 및 릴리스 워크플로를 자동화하는 방법을 더 알아보려면 EAS Workflows 문서를 확인하세요.

[EAS Build](/build/introduction) — Android와 iOS 앱을 컴파일하고 서명하는 방법을 더 알아보려면 EAS Build 문서를 확인하세요.

[EAS Hosting](/eas/hosting/introduction) — Expo Router와 React Native 웹 앱, 그리고 API route를 배포하는 방법을 더 알아보려면 EAS Hosting 문서를 확인하세요.

[EAS Submit](/submit/introduction) — 하나의 CLI 명령으로 앱을 Google Play Store와 Apple App Store에 업로드하는 방법을 더 알아보려면 EAS Submit 문서를 확인하세요.

[EAS Update](/eas-update/introduction) — update를 게시하고 사용자 지정 가능한 전략을 적용하는 방법을 더 알아보려면 EAS Update 문서를 확인하세요.

[EAS Metadata (in preview)](/eas/metadata) — 명령줄에서 앱 스토어 존재감을 자동화하고 유지 관리하는 방법을 알아보려면 EAS Metadata 문서를 확인하세요.

[EAS Insights (in preview)](/eas-insights/introduction) — expo-insights 라이브러리를 사용하는 방법과 정밀한 사용량 지표를 얻는 방법을 더 알아보려면 EAS Insights 문서를 확인하세요. — expo-insights

## eas.json reference

[eas.json schema](/eas/json) — EAS Build와 EAS Submit에서 사용할 수 있는 속성을 더 알아보고, 프로젝트 내부에서 기본 동작을 구성하고 재정의하는 방법을 배우려면 전체 schema reference를 확인하세요.

## Custom builds

[Custom builds](/custom-builds/get-started) — EAS Build를 확장하고 자신만의 구성으로 build 워크플로를 만드는 방법을 알아보려면 custom builds 문서를 확인하세요.

## Relevant guides

[Automate submissions](/build/automate-submissions) — 앱 스토어에서 EAS Build와 함께 자동 제출을 활성화하는 방법을 알아보려면 automate submissions 가이드를 확인하세요.

[GitHub Actions with EAS Update](/eas-update/github-actions) — EAS Update로 update 게시를 자동화하는 방법을 알아보려면 Use GitHub Actions 가이드를 확인하세요.

[App credentials](/app-signing/app-credentials) — Android와 iOS에 필요한 credential 요구 사항을 더 알아보려면 App credentials 가이드를 확인하세요.

[Develop an app with Expo](/workflow/overview) — Expo 앱을 빌드하는 개발 과정을 개괄적으로 살펴보며 핵심 개발 루프의 정신 모델을 세우는 데 도움을 줍니다.
