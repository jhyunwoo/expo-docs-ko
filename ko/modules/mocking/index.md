# Expo 모듈에서 네이티브 호출 mock 처리하기

Expo 모듈에서 네이티브 호출을 mock 처리하는 방법을 알아보세요.

Expo 프로젝트에서 unit test를 작성하는 권장 방식은 [Jest](https://jestjs.io/)와 `jest-expo` preset을 사용하는 것입니다.

네이티브 코드를 사용하는 앱에 대해 unit test를 작성하려면 네이티브 호출을 mock 처리해야 합니다. **mocking**이라는 용어는 함수의 실제 구현을 아무 동작도 하지 않는 가짜 버전으로 대체하는 것을 뜻합니다. 이 접근 방식은 로컬 컴퓨터에서 unit test를 실행할 때 유용한데, 실제 Android 또는 iOS 디바이스에서만 실행할 수 있는 네이티브 코드의 필요성을 우회하기 때문입니다.

Expo SDK에는 각 커뮤니티 패키지에 대한 기본 mock 세트가 포함되어 있습니다. [mock functions](https://jestjs.io/docs/mock-functions) 같은 내장 Jest API를 사용해 원하는 JS 코드도 직접 mock 처리할 수 있습니다.

하지만 Expo 모듈에 기본 mock을 제공하기 위해, 우리는 이를 번들링할 수 있는 방법을 제공합니다. 이렇게 하면 모듈 사용자가 unit test를 실행할 때 자동으로 mock 구현을 사용하게 됩니다.

## 모듈에 mock 제공하기

mock 처리하려는 네이티브 모듈과 동일한 이름의 파일을 만들고, 모듈의 **mocks** 디렉터리에 넣으세요. 이 파일에서 mock 구현을 export해야 합니다. `jest-expo` preset은 unit test 실행 중 `requireNativeModule` 호출이 발생하면 이 파일에서 export한 함수를 자동으로 반환합니다.

예를 들어 `expo-clipboard` 라이브러리에는 `ExpoClipboard`라는 네이티브 모듈이 있습니다. 이를 mock 처리하려면 **mocks** 디렉터리에 **ExpoClipboard.ts** 파일을 만듭니다.

```ts
export async function hasStringAsync(): Promise<boolean> {
  return false;
}
```

이제 unit test에서 `ExpoClipboard.hasStringAsync()`를 호출하면 `false`를 반환합니다.

## mock 자동 생성

네이티브 모듈에 메서드가 많다면 mock을 유지보수하는 일이 꽤 번거로울 수 있습니다. 이를 더 쉽게 하기 위해, 모듈의 **mocks** 디렉터리 안에 있는 모든 네이티브 함수에 대한 mock을 자동으로 생성하는 스크립트를 제공합니다. 이 스크립트는 모듈의 Swift 구현을 기반으로 TypeScript와 JavaScript mock을 생성합니다. Android에서만 존재하는 메서드(예: Kotlin 전용 API)는 자동 생성되지 않습니다. 이런 경우에는 **mocks** 디렉터리에서 직접 mock을 추가하거나 조정해야 합니다.

이 스크립트를 사용하려면 [SourceKitten](https://github.com/jpsim/SourceKitten) framework를 설치해야 합니다. 그런 다음 모듈 디렉터리(모듈의 **expo-module.config.json**이 있는 위치)로 이동해 `generate-ts-mocks` 명령을 실행하세요.

```sh
brew install sourcekitten
npx expo-modules-test-core generate-ts-mocks
```

위 명령은 모듈의 **mocks** 디렉터리에 **ExpoModuleName.ts**를 생성합니다. 이 파일에는 모듈 안의 각 네이티브 메서드와 view에 대한 mock 구현이 들어 있습니다.

> **Tip:** `generate-js-mocks`를 실행해 JavaScript mock도 생성할 수 있습니다.

## mock 처리된 모듈로 unit testing 하기

네이티브 모듈에 대한 mock을 만들었다면, 이제 JavaScript 코드가 네이티브 함수를 올바르게 호출하고 그 응답을 적절히 처리하는지 확인하는 포괄적인 unit test를 작성할 수 있습니다. 예를 들어 `npx expo-modules-test-core generate-ts-mocks` 명령을 실행하면, 아래 예시와 비슷한 mock이 **example-module/mocks** 디렉터리에 생성됩니다:

```ts
/**
 * Automatically generated by expo-modules-test-core.
 *
 * This autogenerated file provides a mock for native Expo module,
 * and works out of the box with the expo jest preset.
 *
 */

export type URL = any;

export function hello(): any {}

export async function setValueAsync(value: string): Promise<any> {}

export type ViewProps = {
  url: URL;
  onLoad: (event: any) => void;
};

export function View(props: ViewProps) {}
```

다음 섹션의 예제는 [`expo-clipboard`](https://github.com/expo/expo/blob/main/packages/expo-clipboard/src/__tests__/Clipboard-test.native.ts), [`expo-screen-capture`](https://github.com/expo/expo/blob/main/packages/expo-screen-capture/src/__tests__/ScreenCaptureHook-test.native.js), [`expo-app-integrity`](https://github.com/expo/expo/blob/main/packages/expo-app-integrity/src/__tests__/ExpoAppIntegrity-test.native.ts) 같은 Expo SDK 모듈의 실제 테스트 기법을 사용한 포괄적인 unit testing 패턴을 보여줍니다.

### 기본 테스트 설정

소스 파일 옆의 **__tests__** 디렉터리에 테스트 파일을 만드세요. 모듈과 mock 처리된 네이티브 모듈을 import해 assertion을 작성합니다:

```js
import * as MyModule from '../MyModule';
import ExpoMyModule from '../ExpoMyModule';

describe('MyModule', () => {
  it('calls native module with correct parameters', async () => {
    await MyModule.doSomething('test-param');
    expect(ExpoMyModule.doSomething).toHaveBeenCalledWith('test-param');
  });
});
```

### 함수 호출과 반환값 테스트하기

Jest의 mock assertion 메서드를 사용해 JavaScript 함수가 네이티브 구현에 올바르게 위임하는지 검증하세요:

```js
describe('Module functionality', () => {
  it('delegates to native implementation', () => {
    MyModule.setData('test-data');
    expect(ExpoMyModule.setDataAsync).toHaveBeenCalledWith('test-data', {});
  });

  it('handles async operations', async () => {
    await expect(MyModule.getDataAsync()).resolves.not.toThrow();
  });

  it('verifies call count', () => {
    MyModule.performAction();
    MyModule.performAction();
    expect(ExpoMyModule.performAction).toHaveBeenCalledTimes(2);
  });
});
```

### 네이티브 모듈을 사용하는 React hook 테스트하기

네이티브 모듈을 사용하는 React hook을 테스트할 때는 React Testing Library의 [`renderHook`](https://testing-library.com/docs/react-testing-library/api/#renderhook) 함수를 사용하세요:

```js
import { renderHook } from '@testing-library/react-native';
import { useMyHook } from '../useMyHook';
import ExpoMyModule from '../ExpoMyModule';

jest.mock('../ExpoMyModule', () => ({
  startOperation: jest.fn().mockResolvedValue(),
  stopOperation: jest.fn().mockResolvedValue(),
}));

describe('useMyHook', () => {
  it('calls native methods on mount and unmount', () => {
    const hook = renderHook(useMyHook);
    expect(ExpoMyModule.startOperation).toHaveBeenCalledTimes(1);

    hook.unmount();
    expect(ExpoMyModule.stopOperation).toHaveBeenCalledTimes(1);
  });

  it('handles parameter changes', () => {
    const hook = renderHook(useMyHook, { initialProps: 'param1' });

    hook.rerender('param2');

    expect(ExpoMyModule.startOperation).toHaveBeenCalledTimes(2);
    expect(ExpoMyModule.stopOperation).toHaveBeenCalledTimes(1);
  });
});
```

### 모범 사례

-   **테스트 사이 정리하기**: `beforeEach` 또는 `afterEach`를 사용해 mock을 초기화하고 테스트 간 오염을 방지하세요.
-   **엣지 케이스 테스트하기**: 네이티브 함수가 오류를 던지거나 예기치 않은 값을 반환할 때의 동작을 검증하세요.
-   **설명적인 테스트 이름 사용하기**: 검증하는 구체적인 동작이 드러나는 테스트 설명을 작성하세요.
-   **관련 테스트를 묶기**: `describe` 블록을 사용해 기능이나 컴포넌트별로 테스트를 정리하세요.
